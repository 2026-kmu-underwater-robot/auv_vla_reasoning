데이터셋 제작기와 수집기의 `collector.py` 및 `contract.py`는 줄바꿈 형식을 제외하면
같았습니다. 두 레포가 동일한 ROS 패키지 이름을 사용하므로, 새 추론 패키지가 어느 한쪽
패키지를 덮어쓰거나 경로 순서에 따라 다른 수집기를 불러오지 않도록 의존을 분리했습니다.

## 재사용한 구현

- 모델 네트워크, action head, 이미지/상태 전처리, 토크나이저 자료는 기존 U0/GR00T 코드입니다.
  `auv_vla_reasoning/_vendor/gr00t/`에 필요한 소스만 보존했습니다. 원본 저작권 헤더와
  Apache-2.0 라이선스를 유지했습니다.
- 앞서 작성한 [실물 학습 수정 PR](https://github.com/2026-kmu-underwater-robot/auv_vla/pull/2)의
  `c6d3f7e4c3f7ec4a5d3792df2f91d9fe533c12f5`에서 v2 전처리와 bf16 모델 로딩 관련 수정을
  가져왔습니다. 이 PR은 확인 시점에 미병합 상태였습니다. 기존 모델은 legacy 전처리를
  기본으로 유지하고, v2로 학습된 모델만 명시적으로 v2를 선택합니다.
- [실물 수집 수정 PR](https://github.com/2026-kmu-underwater-robot/auv_vla_data_collector/pull/2)의
  `7aa22b89ca3ceb9d6f5cf6c8fc56df781999c613`도 센서 유효성 처리 검토에 참고했습니다.
  이 PR 역시 확인 시점에 미병합 상태였습니다.
- 기존 `RovPolicyAdapter`의 비활성 시작, deadman, 모드 확인, 명령 제한, 오래된 입력/출력
  거부, 채널 해제 동작을 유지했습니다.

## 실물 추론을 위해 변경한 부분

1. **수집과 추론 분리:** 센서 전용 `vla_observation` 노드에서 입력을 읽습니다.
   녹화 타이머·서비스·파일 저장·RC 기록 구독은 제거했습니다.
2. **잘못된 센서 값 처리:** IMU가 특정 측정값을 제공하지 않는다고 표시하거나 깊이/영상이
   무효하면 이전 캐시를 유효한 값으로 계속 쓰지 않습니다. 빈 작업 설명은 기존 지시를 해제합니다.
3. **실물 시간과 영상:** 시뮬레이션 시간을 거부하고, 원본/수신 시각을 모두 확인합니다.
   IMX219 compressed 영상을 기본으로 두고 명시적으로 선택한 raw RGB/BGR 영상도 받습니다.
4. **모델 설정 확인:** 모델의 두 카메라·상태·4축 출력, 16개 명령, CAP 비활성 설정,
   로컬 가중치 파일을 검사합니다. 시뮬 전용 모델 표식은 거부합니다.
   가중치 내부 내용과 모델 품질은 `--check_only`가 검증하지 않습니다.
5. **전처리 유지:** legacy 모델은 검토한 별도 조종 설정 JSON이 필요합니다.
   v2 모델은 학습 때 저장된 설정을 사용하고, 다른 범위나 전처리 설정으로 바꾸지 않습니다.
6. **HTTP 입출력:** NumPy 입력과 기존 `[actions, null]` 응답 형식을 지원합니다.
   추론은 직렬로 처리하며, 무효·비정상 범위 출력은 오류로 반환합니다.
7. **모델/조종기 설정 대조:** 활성화 시 서버와 채널·PWM 범위·모드·주기를 대조합니다.
   서버가 재시작되면 이전 식별자로 보낸 요청은 거부되어 재확인 없이 조종이 이어지지 않습니다.
8. **운용 중단과 종료:** 작업 변경, 다른 RC 발행자, 기한 초과 시 중단합니다.
   이전 활성화의 실패 응답이 새 활성화에 영향을 주지 않게 처리하고,
   정상 SIGINT/SIGTERM 종료에서는 ROS 컨텍스트가 살아 있는 동안 조종 채널을 해제합니다.

## 확인된 연결 범위

- GUI가 시작한 ROV/카메라의 토픽을 구독하지만 GUI 버튼은 추가하지 않았습니다.
- 기본 카메라 두 뷰는 학습 데이터와 일치해야 합니다. RealSense 실행만으로 분리부 시야가
  준비됐다고 판단하지 않습니다. DVL/IMU의 장착 방향을 임의로 추정하지 않습니다.
- `auv_vla_dataset_maker`는 LeRobot v3를 출력하지만 현재 `auv_vla`의 학습 로더는
  `meta/episodes.jsonl`, `meta/tasks.jsonl` 기반 v2 형식을 읽습니다. 학습기의 v3 지원은
  별도 작업이며 여기서 해결했다고 주장하지 않습니다. 실시간 추론에는 데이터셋 로딩을 쓰지 않습니다.
- 실제 FCU의 PWM/모드 설정을 읽어 자동 보정하지 않습니다. 학습·서버·ROS 설정을 서로 대조합니다.
- 모델 가중치, PPO, 시뮬 설정, 데이터셋과 기체 제어 시험은 포함하지 않았습니다.

소스 파일별 해시와 출처는 [SOURCES.json](SOURCES.json)에 기록했습니다.
