# 검증 기록

2026-10-07, 실제 기체나 외부 ROS 네트워크에 연결하지 않고 확인했습니다.

| 검증 | 결과 |
|---|---|
| 일반 Python 테스트 | 78개 통과, ROS가 필요한 항목 23개 건너뜀 |
| ROS Humble의 센서·어댑터·조종값 테스트 | 64개 통과 |
| Black / Ruff | 직접 작성·변경한 추론 코드, 테스트, 설치·런치 파일 통과 |
| colcon 빌드 | `auv_vla_reasoning` 패키지 빌드 성공 |
| ROS 런치 | 설치된 패키지 검색 및 `reasoning.launch.py --show-args` 성공 |
| Python wheel | 가중치 없이 배포 패키지 생성·별도 위치 설치 성공 |
| 설치된 패키지의 공통 모델 코드 | 원본 폴더 밖에서 import 성공, 토크나이저 자료·legacy/v2 전처리·16개 출력 설정 확인 |

두 테스트 묶음에는 공통 검사가 포함되므로 숫자를 합산한 고유 테스트 수는 아닙니다.
CUDA 모델을 대체한 가짜 정책으로 HTTP 입출력을 확인했습니다.

검사 범위는 다음과 같습니다.

- legacy/v2 설정, 시뮬 모델 거부, CAP 비활성, 누락된 가중치/metadata/분할 가중치
- 실제 NumPy JSON 왕복, 입력/출력 크기, 비정상 수치, 서버 재시작 식별, 동시 추론 직렬화
- compressed/raw 영상의 RGB 순서, stride, 두 카메라 필수 입력, 센서 시각과 무효 데이터
- FRD→FLU, wxyz 자세, DVL 없음, 23개 상태값, 작업 설명 비우기
- deadman·FCU 상태·PWM 범위·타임아웃, 이전 추론 응답, 작업 변경, RC 발행자 충돌
- 활성화 중 메타데이터 조회 지연, 정상/외부 ROS 종료, 시뮬 시간 변경 거부

원본 수집기 콜백으로 바꾼 격리 검증에서 센서 관련 회귀 검사 4개가 실패했고,
수정된 구현으로 다시 실행하면 통과했습니다. 원본 저장소 파일은 바꾸지 않았습니다.
ROS 어댑터 검토에서는 이전 요청 실패·활성화 지연·종료 시 컨텍스트·시간 설정 문제를
별도 격리 실행으로 재현한 뒤 해당 검사와 수정을 추가했습니다.

실제 학습 가중치를 로딩한 전체 GPU 추론, 실제 FCU 명령, 수중 시험, 지연 시간과 모델
성능은 검증하지 않았습니다. 설치/설정 검사는 그러한 시험의 성공을 의미하지 않습니다.
기본 0.3초 명령 유효 시간 안에 실제 서버가 응답하는지도 장비에서 측정해야 합니다.
